# TypeScript 어드민 템플릿 설계

FastAPI · NestJS · Rails 세 백엔드 템플릿이 공유하는 JSON:API 1.1 계약을
**운영자 관점에서** 소비하는 Next.js 어드민 템플릿의 설계다.

## 0. 이 문서의 위치

이 문서는 구현 전 설계의 정본이다. 계층 계약의 운용 정본은 구현 후 루트
`AGENTS.md`가 소유하고, 이 문서는 **왜 그 계약인가**를 소유한다.

측정은 모두 2026-09-12 에 실제 저장소를 읽어 수행했다. 측정 대상 커밋은
2장에 적는다 — 날짜가 붙은 측정 결과는 그 시점의 관측이며, 계약이 바뀌면
이 문서가 아니라 새 측정이 정본이 된다.

## 1. 목적과 경계

### 1.1 무엇인가

`template-typescript-nextjs`와 **동일한 JSON:API 계약을 소비하는 별개의
운영자용 앱**이다. 전환은 `BACKEND_URL` 하나이고 어댑터 계층이 없다 — 세
백엔드의 공개 계약이 통일되어 있으므로 이 앱도 어느 백엔드를 상대하는지
몰라도 된다.

고객용 앱과 갈라지는 지점은 **화면의 밀도와 작업 단위**다. 고객은 한 번에
한 건을 다루고, 운영자는 수십 건을 훑어 고른 뒤 한꺼번에 처리한다. 그래서
이 템플릿이 실증하는 것은 계약이 아니라 **계약 위에 세운 운영 UX**다 — 열
구성, 다중 선택과 일괄 작업, 살아있는 필터 뷰, 키보드 항해, 인라인 편집.

### 1.2 무엇이 아닌가

**백엔드를 바꾸지 않는다.** 세 백엔드 저장소에 커밋 하나도 넣지 않는다. 이
경계가 이 템플릿의 범위를 결정한다 — 백엔드 계약에 없는 기능은 프론트엔드
만으로 만들 수 없으므로 넣지 않는다(10장).

`template-typescript-nextjs`도 **고치지 않는다.** 3장의 조달 방식이 그
저장소를 읽기만 하는 이유다.

## 2. 측정한 백엔드 계약

측정 대상 커밋. 세 백엔드는 `template-typescript-nextjs`가 자기 README 에
"검증 완료"로 기록한 커밋과 같다 — 즉 아래 계약은 240회 E2E 로 검증된
계약이다.

| 저장소                       | 커밋      |
| ---------------------------- | --------- |
| `template-python-fastapi`    | `3c4eee3` |
| `template-typescript-nestjs` | `4d49f3a` |
| `template-ruby-rails`        | `231576e` |
| `template-typescript-nextjs` | `34d0b10` |

### 2.1 노출되는 표면 전부

정본(FastAPI) `config/routes.py`가 조립하는 라우터는 여섯이다.

| 표면                 | 내용                                        |
| -------------------- | ------------------------------------------- |
| `/api/v1/auth`       | `register` · `login` · `refresh` · `logout` |
| `/api/v1/users`      | **`GET /me` 하나뿐**                        |
| `/api/v1/examples`   | 자원 전체 — 아래 2.2                        |
| `/api/v1/categories` | 읽기 전용 참조 자원                         |
| `/api/v1/tags`       | 읽기 전용 참조 자원                         |
| `/health/live` · `/health/ready` | `live` 는 무조건 ok. `ready` 는 `SELECT 1` 로 Postgres 를 확인하고 실패 시 **503** |

### 2.2 자원별 라우트

`app/controllers/concerns/route_registrar.py`가 등록하는 것.

```
GET    ""                              index   (filter · sort · page)
POST   ""                              create
GET    "/{id}"                         show
PATCH  "/{id}"                         update
PUT    "/{id}"                         upsert
DELETE "/{id}"                         destroy
GET    "/{id}/relationships/{name}"    relationship show
GET    "/{id}/{name}"                  related
PATCH  "/{id}/relationships/{name}"    relationship 변경
POST   "/{id}/relationships/{name}"    relationship 추가
DELETE "/{id}/relationships/{name}"    relationship 제거
```

### 2.3 없는 것 — 그리고 그것이 정하는 경계

**모델에 없다.** `app/models/`에 있는 것은 `user` · `refresh_session` ·
`example` · `example_category` · `example_tag` · `email_identity_backup`
여섯이다. `role` · `permission` · `audit_log`는 **없다.**

`user`의 칼럼은 `id` · `email` · `password_hash` · `is_active`와
타임스탬프다. **역할을 담을 칼럼이 없다.**

**라우트에 없다.** `bulk` · `batch` · JSON:API 1.1 의 `atomic:operations`
가 어느 컨트롤러에도 없다.

**관리자용 사용자 프로비저닝이 없다.** `users`는 `GET /me`만 있고, 계정을
만드는 경로는 셀프 가입인 `POST /auth/register` 하나다.

이 셋이 각각 10장의 배제, 6장의 일괄 작업 설계, 7장의 첫 운영자 절차를
정한다. **세 결정 모두 취향이 아니라 측정 결과다.**

## 3. 코어 조달 — 복사해 독립

### 3.1 결정

`lib/jsonapi/` · `lib/auth/` · `lib/config/` · `proxy.ts`와 그 단위 테스트를
`template-typescript-nextjs`에서 **복사한다.** 두 저장소는 코드 의존이 없다.

복사 대상의 규모(측정):

| 계층           | 크기   | 파일 | 하는 일                                                         |
| -------------- | ------ | ---- | --------------------------------------------------------------- |
| `lib/jsonapi/` | 62 KB  | 6    | 문서 파싱, `included` 정규화, 쿼리 직렬화, 오류 분류, HTTP 협상 |
| `lib/auth/`    | 82 KB  | 9    | 쿠키 세션, 만료 판정, 토큰 회전, 로그아웃, 자격증명             |
| `lib/config/`  | 3.8 KB | 2    | 설정 정본                                                       |
| `proxy.ts`     | 15 KB  | 1    | 경로 가드, 토큰 회전                                             |

이 코어를 지키는 단위 테스트는 `test/unit/` 전체 566 KB · 52 파일 · 938개의
일부이고, 그 위에 실제 백엔드 3종 E2E 240회 통과 이력이 있다.

### 3.2 왜 공유 패키지가 아닌가

공유 패키지(pnpm workspace 또는 배포 패키지)는 드리프트를 구조적으로 막지만
셋을 대가로 요구한다. **첫째,** 성숙한 `template-typescript-nextjs`를
재구조화해야 한다. **둘째,** 버전·배포 인프라가 생긴다. **셋째, "클론하면
돈다"가 깨진다** — 템플릿의 존재 이유가 그것이다.

세 백엔드 템플릿이 이미 같은 트레이드오프를 받아들이고 있다. 그 셋은 하나의
계약에 대한 **독립 구현 셋**이고, 정합성을 공유 코드가 아니라 계약 거울
테스트와 실제 백엔드 E2E 로 지킨다. 그 방식이 작동한다는 증거가 240회다.
어드민도 같은 방식으로 묶는다.

새로 구현하는 안은 검토 후 버렸다 — 938개 테스트로 지켜지는 자산을 버리고
같은 계약의 해석을 둘로 만드는 것이 이 패밀리가 존재하는 이유에 반한다.

### 3.3 드리프트를 감사 가능하게 만드는 장치

**복사해 온 계층은 출처 커밋을 기록한다.** 출처가 적히지 않은 사본은
드리프트를 감사할 수 없다 — 몇 달 뒤 "이 버그가 nextjs 에서도 고쳐졌나"를
물을 수 있어야 한다.

기록 위치와 형식은 구현 계획이 정한다. 요구사항은 둘이다.

1. 복사 시점의 `template-typescript-nextjs` 커밋 SHA 가 저장소 안에 있다.
2. 사람이 아니라 **검사가** 그 기록의 존재를 확인한다 — 기록을 사람의 기억에
   두면 다음 복사에서 갱신되지 않는다(인용 규칙이 같은 이유로 게이트로
   옮겨졌다).

### 3.4 어드민 UI 의 출발점 — shadcn `dashboard-01` (2026-09-12 결정)

**어드민 화면의 디자인은 손으로 만들지 않는다.** shadcn 공식 블록을 그대로
가져와 출발점으로 쓴다.

```bash
npx shadcn@latest add dashboard-01
```

스타일은 `base-nova` 로, `template-typescript-nextjs` 의 `components.json`
과 같다 — 블록이 패밀리의 생김새를 그대로 따른다.

이 결정이 3.3 까지의 조달 방식과 겹치지 않는다는 점에 주의한다. **코어
(`lib/jsonapi` · `lib/auth` · `lib/config` · `proxy.ts`)는 nextjs 템플릿에서
복사하고, UI 부품과 셸은 shadcn 레지스트리에서 받는다.** 출처가 둘이고
각각의 이유가 다르다.

#### 블록이 가져오는 것

| 종류         | 내용                                                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 화면         | `page.tsx` — `SidebarProvider` · `AppSidebar variant="inset"` · `SidebarInset` · `SiteHeader` · `SectionCards` · `ChartAreaInteractive` · `DataTable` |
| 부품         | `app-sidebar` · `nav-main` · `nav-documents` · `nav-secondary` · `nav-user` · `site-header` · `section-cards` · `chart-area-interactive` · `data-table`(32 KB) |
| npm 의존성   | `@tanstack/react-table` · `@dnd-kit/core` · `@dnd-kit/modifiers` · `@dnd-kit/sortable` · `@dnd-kit/utilities` · `zod`                        |
| 레지스트리   | 19개 — 패밀리에 이미 있는 6개(`label` · `select` · `table` · `badge` · `button` · `input`)와 **새로 들어오는 13개**                          |

새로 들어오는 13개: `sidebar` · `breadcrumb` · `separator` · `chart` ·
`card` · `tabs` · `toggle-group` · `checkbox` · `dropdown-menu` · `drawer` ·
`avatar` · `sheet` · `sonner`.

이 13개가 어드민이 필요로 하면서 패밀리에 없던 부품을 정확히 덮는다 —
사이드바, 체크박스(다중 선택), 드롭다운(열 구성), 아바타, 브레드크럼,
카드. **`globals.css` 에 `--sidebar-*` 토큰이 이미 정의돼 있고 nextjs 가
쓰지 않는 이유가 이것이다** — shadcn `sidebar` 컴포넌트가 그 토큰을
요구한다. 어드민이 그 토큰의 첫 소비자다.

#### 무엇을 그대로 쓰고 무엇을 갈아끼우는가

**레이아웃과 부품은 그대로 쓴다.** 셸 구조, 사이드바, 헤더, 카드 그리드,
표의 생김새를 고치지 않는다.

**데이터 배선은 반드시 갈아끼운다.** 블록이 들고 오는 내용은 이 제품의
것이 아니고 백엔드 계약에 대응하는 것이 하나도 없다.

| 블록이 들고 오는 것                                                       | 우리 계약의 대응   | 처분                         |
| ------------------------------------------------------------------------- | ------------------ | ---------------------------- |
| `section-cards` 의 Total Revenue `$1,250.00` · New Customers · Growth Rate | **없다** — 2장     | 2장의 자원 카운트로 교체     |
| `data.json` 68행(`header` · `target` · `limit` · `reviewer: "Eddie Lake"`) | `examples`         | `examples` 로 교체           |
| `chart-area-interactive` 의 90일치 `chartData`(파일에 박혀 있다)           | **없다** — 3.4.1   | **남긴다 — 표본으로 명시**   |
| `data-table.tsx` 의 dnd-kit 드래그 정렬                                   | **없다** — 3.4.2   | **남긴다 — 손대지 않는다**   |

카드와 표는 갈아끼운다. 그대로 두면 백엔드를 보지 않는 데모 화면이 되어
1.1 이 말한 "`BACKEND_URL` 하나로 계약을 소비한다"가 깨진다.

#### 3.4.1 차트는 남기되 표본임을 화면이 말한다

백엔드에 시계열도 집계 엔드포인트도 없다(2.3). 그래서 `chartArea` 의
데이터는 **블록이 들고 온 배열 그대로** 남는다. 대신 **표본이라는 사실을
화면과 문서가 명시한다** — 그것이 이 결정의 조건이다.

- 차트 카드에 **백엔드에 연결되지 않은 표본 데이터**임이 적혀 있어야 한다.
  운영자가 이 숫자를 읽고 판단하면 안 된다는 것을 화면에서 알 수 있어야
  한다.
- `README.md` 와 `AGENTS.md` 가 같은 사실을 적는다 — 클론한 사람이 무엇을
  갈아끼워야 하는지 알아야 한다.

집계를 클라이언트에서 만드는 안은 버렸다. 집계 엔드포인트가 없어 전건을
쪽 단위로 순회해야 하고, 그러면 화면 진입 한 번이 요청 수십 개를 낸다 —
6.2 가 기록한 그 함정이다.

#### 3.4.2 dnd-kit 드래그 정렬은 손대지 않는다

백엔드에 정렬 수서 필드도, 재정렬 엔드포인트도 없다(2.2 · 2.3). 그래서
드래그로 옮긴 순서는 **서버에 남지 않고 새로고침하면 사라진다.**

그럼에도 블록의 부품을 고치지 않는다 — 나중에 백엔드가 순서를 갖추면
배선만 하면 된다. **대가는 알고 받는다**: 지금 이 기능은 동작하는 것처럼
보이지만 지속되지 않는다. `@dnd-kit/*` 의존성 넷도 그래서 남는다.

이 사실을 `AGENTS.md` 가 적는다. 적지 않으면 다음 사람이 "드래그가 저장이
안 되는 버그"로 읽고 없는 엔드포인트를 찾는다.

## 4. 계층 소유권

**아래 표는 소유 관계이지 파일 목록이 아니다.** 어떤 위치가 아직 비어 있어도
그 행의 계약은 이미 유효하다.

| 위치               | 소유하는 것                                                     | 소유하지 않는 것        |
| ------------------ | --------------------------------------------------------------- | ----------------------- |
| `lib/jsonapi/`     | 문서 파싱, `included` 정규화, 쿼리 직렬화, 오류 분류, HTTP 협상 | 자원별 지식, 화면       |
| `lib/resources/`   | 자원의 타입·필터·정렬·폼 스키마·표시 라벨                       | JSX, `fetch`            |
| `lib/grid/`        | URL 이 말하는 목록 상태 → 백엔드 질의로의 변환, URL 직렬화       | JSX, `fetch`, 자원 분기 |
| `lib/bulk/`        | 일괄 실행기 — 순차 실행, 부분 실패 집계, 취소                   | JSX, 자원 분기          |
| `lib/auth/`        | 쿠키 세션, 토큰 만료 판정, 가드                                 | 화면 이동 결정          |
| `lib/config/`      | 환경 변수 해석의 정본 — 필수 변수의 시작 실패 판정              | 자원별 지식, 화면       |
| `proxy.ts`         | 보호 경로 목록, 경로 가드, 토큰 회전                            | 화면, 자원별 지식       |
| `app/`             | 화면, Server Action, 라우팅                                     | `fetch`, 쿼리 조립      |
| `components/grid/` | 자원 선언을 읽어 만드는 획일 그리드 UI                          | 자원별 분기             |

위반의 정의:

- `lib/jsonapi/` · `lib/grid/` · `lib/bulk/`에 이 저장소의 실제 자원 이름을
  가리키는 문자열 리터럴이 **코드로**(주석의 설명적 언급이 아니라) 나타나면
  위반이다.
- `lib/resources/*.ts` · `lib/grid/*.ts` · `lib/bulk/*.ts`에 JSX 가 있으면
  위반이다.
- `app/`에서 `fetch`를 직접 부르면 위반이다.
- `components/grid/*`에 자원 이름으로 분기하는 코드가 있으면 위반이다.

`lib/resources/index.ts`는 손으로 채우는 배열이다. **여기 없으면 그 자원은
존재하지 않는 것과 같다.** 자동 탐색(glob · `import.meta.glob` · 동적
`import`)을 쓰면 이 계약이 사라진다.

### 4.1 왜 `lib/grid/`와 `lib/bulk/`를 떼는가

`template-typescript-nextjs`는 화면의 판단 전부를 `lib/resources/view.ts`
한 파일에 모았고 **그 파일이 99 KB 다**(측정). 그 저장소에서는 합리적인
선택이었다 — 목록·상세·폼 셋의 판단만 들어간다.

어드민은 여기에 열 구성, 선택 집합, 필터 뷰, 일괄 실행의 진행·부분 실패
상태가 더해진다. 같은 자리에 넣으면 반드시 더 커진다. 파일이 커지면 사람도
에이전트도 한 번에 들고 읽을 수 없고, 그만큼 편집이 부정확해진다.

그래서 **경계를 세 개로 나눈다.** `lib/resources/`는 "자원이 무엇인가",
`lib/grid/`는 "지금 무엇을 보고 있는가", `lib/bulk/`는 "무엇을 실행하는
중인가"를 소유한다. 셋은 각각 독립적으로 단위 테스트된다.

### 4.2 TanStack Table 과의 경계 — 정렬·필터·페이지는 서버가 소유한다

3.4 가 `dashboard-01` 을 출발점으로 정했으므로 표는 그 블록의
`data-table.tsx`(TanStack Table)로 그린다. 그런데 **그 블록은 정적인 68행
JSON 위에서 클라이언트가 정렬·페이지를 다 하는 모양이다.** 우리 데이터는
서버가 페이지를 끊는다(1,284건, 쪽당 최대 100).

그대로 쓰면 **불러온 한 쪽 안에서만 정렬·페이지가 일어난다.** 화면은
정상으로 보이고 값도 그려지므로, 목록 전체가 정렬된 것처럼 읽힌다 —
조용히 틀리는 자리다.

그래서 경계를 이렇게 고정한다.

| 누가            | 소유하는 것                                                    |
| --------------- | -------------------------------------------------------------- |
| 백엔드          | 정렬 · 필터 · 페이지 — JSON:API 질의 매개변수가 정본이다       |
| `lib/grid/`     | URL ↔ 질의 매개변수 변환. 단위 테스트가 이 변환을 고정한다     |
| TanStack Table  | 불러온 쪽의 렌더링, 행 선택, 열 표시/숨김                      |

**끄는 방법은 설치된 버전이 정한다.** 실측(2026-09-12): `shadcn add
dashboard-01` 이 들여온 것은 `@tanstack/react-table@9.2.4` 이고, v9 에서는

| 무엇 | 방법 |
| ---- | ---- |
| 페이지 | `manualPagination: true` 와 **서버 총합 `rowCount`** 를 함께 준다 |
| 정렬   | `sortedRowModel` 을 **등록하지 않는다** |
| 필터   | `filteredRowModel` 을 **등록하지 않는다** |

**`manualSorting` · `manualFiltering` 은 v9 에 존재하지 않는다** — 패키지
전체에서 0건이다. 주면 인식되지 않고 조용히 무시되므로, 그 이름에 의존한
테스트는 초록인 채로 표가 계속 불러온 쪽만 정렬한다. 이 스펙의 앞선 판이
정확히 그 처방을 담고 있었다.

즉 **v9 에서는 행 모델의 부재가 곧 계약이다.** 그 부재를 재는 테스트를
둔다 — 등록을 되살리는 뮤턴트가 화면상 아무 증상을 내지 않기 때문이다.
`rowCount` 를 빼면 표가 전체 쪽 수를 계산할 수 없다.

실측(2026-09-12, 레지스트리에서 받은 `data-table.tsx`): 블록은
`createFilteredRowModel()` · `createSortedRowModel()` ·
`createPaginatedRowModel()` 셋을 **등록하고** `manual*` 플래그를 하나도 두지
않는다. 페이지 상태는 컴포넌트 안의 `useState`(`pageSize: 10`)다. 즉 위
결함은 잠재적인 것이 아니라 **받은 그대로의 기본 동작**이다.

끄는 방법은 둘이고 동등하다 — `manual*: true` 를 주거나, 해당
`create*RowModel` 등록을 생략한다(`table_getPaginatedRowModel` 이 둘을 같은
분기로 처리한다). 어느 쪽을 쓰는지는 구현이 정하되 **셋을 함께** 처리한다:
TanStack 문서 자신이 "manual pagination 을 쓰면 manual sorting 도 켜야
한다 — 그렇지 않으면 불러온 쪽만 정렬하려 든다"고 경고한다. 우리가 겪을
증상이 정확히 그것이다.

앞선 판에서는 그리드 상태 전부를 `lib/grid/`가 갖고 테이블 라이브러리를
쓰지 않기로 했다. 3.4 의 결정이 그것을 뒤집었고, 위 표가 새 계약이다.

## 5. 운영 UX 표면

### 5.1 화면

경로의 정본은 `app/`의 파일 배치이고, **인증 필요 여부의 정본은 `proxy.ts`의
`PROTECTED_PATH_PATTERNS`다.**

| 경로             | 인증 | 내용                                                                  |
| ---------------- | ---- | --------------------------------------------------------------------- |
| `/`              | 필요 | 대시보드 — `dashboard-01` 의 카드·차트·표 구성(3.4)                   |
| `/examples`      | 필요 | 운영 그리드 — 열 구성 · 다중 선택 · 일괄 작업 · 필터 뷰 · 키보드 항해 |
| `/examples/[id]` | 필요 | 상세 + 인라인 편집                                                    |
| `/examples/new`  | 필요 | 생성                                                                  |
| `/login`         | 공개 | 로그인                                                                |

**공개 표면은 `/login` 하나다.** 이것이 `template-typescript-nextjs`와 가장
크게 갈라지는 자리다 — 그쪽은 목록·상세가 공개이고 쓰기만 보호된다. 어드민은
읽기조차 운영자만 본다.

자원은 백엔드가 가진 것뿐이다 — `examples`(전체 CRUD)와 참조 자원
`exampleCategories` · `exampleTags`(읽기 전용), 그리고 `users/me`.

### 5.2 라우트 그룹

| 그룹      | 껍데기                 | 무엇이 들어가나                        |
| --------- | ---------------------- | -------------------------------------- |
| `(admin)` | 사이드바 셸            | 대시보드와 자원 화면. 새 화면은 여기다 |
| `(auth)`  | 뷰포트 전체, 헤더 없음 | 로그인                                 |

`(lab)`은 만들지 않는다 — 계약 실험실은 `template-typescript-nextjs`가
소유하고, 두 저장소가 같은 실증을 중복으로 들고 있을 이유가 없다.

`(admin)` 안에서 `min-h-svh`를 쓰지 않는다. 높이는 셸이 갖는다 — 화면이 다시
잡으면 헤더 높이만큼 넘친다.

### 5.3 로딩 상태

**스켈레톤만 둔다. 텍스트를 하나도 쓰지 않는다.** 열 수는 선언에서
가져온다 — 박으면 선언과 갈라진다.

## 6. 일괄 작업

### 6.1 제약

벌크 엔드포인트가 없다(2.3). 20행 삭제는 `DELETE` 20회다. 이 사실이 아래
셋을 정한다.

### 6.2 순차 실행과 상한

동시성을 묶고 최대 건수를 명시한다. `template-typescript-nextjs`가 같은
함정을 이미 기록해 뒀다 — 계약 실험실의 익명 클릭 한 번이 커서 순회로 백엔드
요청 최대 스무 개를 낸다는 경고다. 어드민의 일괄 작업은 그것을 **의도적으로**
하는 기능이므로, 상한과 동시성이 기능의 일부다.

상한의 구체적 값은 구현 계획이 정한다. 요구사항은 값이 **선언된 자리 하나에
있고** 화면이 그 값을 읽어 사용자에게 미리 알린다는 것이다.

### 6.3 부분 실패는 1급 결과다

**무엇이 실제로 실패하는가** (실측 2026-09-12, `app/controllers/concerns/crud_actions.py` 의 `destroy`): 성공은 **204** 다. 거절 경로는 순서대로 `reject_query_parameters` → `_find_resource`(없으면 **404**) → `before_destroy` 훅 → 삭제다. `ExamplesController` 는 그 훅을 재정의하지 않고, `example_tags` 는 `ondelete="CASCADE"` 라 **태그가 붙은 자원도 그냥 지워진다** — 참조 무결성 때문에 거절되는 경로가 없다.

그래서 현실적인 부분 실패는 둘이다.

| 상태 | 언제 |
| ---- | ---- |
| **404** | 그 행이 이미 없다 — 다른 운영자가 지웠거나 목록이 낡았다 |
| **401** | 실행 중 세션이 만료됐다 — 요청 N 회가 순차로 나가는 동안 |

**404 가 이 화면의 주된 이야기다.** 운영자 둘이 같은 그리드를 보는 어드민에서 가장 자주 일어나고, 사용자에게 하는 말이 분명하다 — *목록이 낡았다, 고르는 동안 누가 지웠다.*

이 스펙의 앞선 판은 "12행 중 3행이 422 로 죽는다"를 예로 들었다. **백엔드는 삭제에 422 를 내지 않는다** — 지어낸 예였고, 그 위에 세운 E2E 시나리오(삭제가 거절되는 씨앗 행을 심는다)는 만들 수 없는 상태를 요구했다.

12행 중 3행이 죽는 것이 **정상 경로**다. 그래서:

- 토스트로 뭉개지 않는다. **행별 성공·실패를 결과 표로 낸다.**
- 실패한 행만 재시도할 수 있다.
- 실패 이유는 백엔드가 준 JSON:API 오류에서 온다 — 프론트엔드가 문구를
  만들지 않는다. 오류 문구의 정본은 백엔드다.

### 6.4 취소

진행 중 중단하면 **남은 요청을 내지 않는다.** 이미 보낸 것은 되돌리지
않는다 — 보상 트랜잭션을 만들지 않는다(백엔드 계약이 없다). 취소 시점까지의
결과는 6.3의 결과 표에 그대로 남는다.

### 6.5 어디서 관측되는가

부분 실패·취소·제출 중 상태는 **E2E 로만 관측된다.** 이 패밀리는
`next/headers`의 `cookies()`·`headers()`와 `next/navigation`의 `redirect()`를
vitest 에서 스텁하지 않는 관례를 갖는다(스텁이 실제 런타임과 어긋나면 초록인
채로 틀린다). Server Action 의 왕복이 정확히 그 자리다.

반대로 `lib/bulk/`의 실행기 자체 — 순서, 상한, 집계, 취소 신호 처리 — 는 순수
함수로 두어 단위가 전부 지킨다. **실행기는 단위가, 배선은 E2E 가** 지킨다.

## 7. 인증과 첫 운영자

### 7.1 가입 화면을 두지 않는다

운영자는 자기 가입을 하지 않는다. `/register`를 만들지 않는다.

### 7.2 그래서 생기는 문제

백엔드에 관리자용 계정 생성 경로가 없다(2.3). 가입 화면을 지우면 **첫
운영자를 만들 방법이 템플릿 안에서 사라진다.**

### 7.3 해결 — 시드 스크립트, 그리고 그것을 E2E 가 실행한다

첫 운영자는 백엔드의 `POST /auth/register`를 한 번 호출하는 시드 스크립트로
만든다. 절차의 정본은 `README.md`와 `AGENTS.md`가 소유한다.

**핵심은 그 경로를 E2E 가 실제로 쓴다는 것이다.** 어드민에는 공개 표면이
없으므로 E2E 가 어떤 화면에든 닿으려면 먼저 운영자가 있어야 하고,
`/register` 화면이 없으므로 E2E 는 **백엔드 계약에 직접** 운영자를 만든다.
그 프로비저닝과 시드 스크립트가 **같은 함수를 쓴다.**

그래서 시드 절차가 문서에만 있는 죽은 절차가 되지 않는다 — E2E 를 돌릴
때마다 실행된다. 시드가 깨지면 게이트가 빨개진다.

E2E 의 이메일은 **실행마다·테스트마다 달라야 한다.** 중복 가입은 409 라
재실행이 조용히 다른 갈래를 탄다. 이메일 로컬 파트는 RFC 5321 의 64자를
넘지 않아야 한다 — nextjs 저장소가 실측으로 배운 함정이고, 세 백엔드 중 일부만
우연히 너그러웠다.

### 7.4 환경 변수

앱이 읽는 변수는 `template-typescript-nextjs`와 같은 계약이다.

| 변수                    | 필수   | 기본값                      | 무엇                                        |
| ----------------------- | ------ | --------------------------- | ------------------------------------------- |
| `BACKEND_URL`           | 예     | 없음                        | 백엔드 API 의 절대 URL. 끝 슬래시는 잘린다  |
| `SESSION_COOKIE_SECURE` | 아니오 | `NODE_ENV === 'production'` | 세션 쿠키의 `Secure` 속성. `true`/`false`만 |

**필수 변수에 코드상의 암묵적 기본값을 두지 않는다.** `BACKEND_URL`이 없으면
시작에 실패한다 — 첫 요청에서야 드러나는 설정 오류보다 시작 실패가 낫다.
백엔드 템플릿들의 `DATABASE_URL`과 같은 계약이다.

E2E 만 읽는 변수 다섯(`E2E_WEB_PORT` · `E2E_API_PORT` · `BACKEND_KIND` ·
`E2E_KEEP_STACK` · `CI`)도 같은 계약을 따른다. **앱은 이 다섯을 하나도
모른다.**

## 8. 게이트와 테스트

### 8.1 단일 게이트

`./scripts/check.sh` 하나가 유일한 게이트다. 단계는
`template-typescript-nextjs`의 아홉을 그대로 물려받는다.

```
[1/9] typecheck   [2/9] lint       [3/9] format
[4/9] secretlint  [5/9] 인용        [6/9] unit
[7/9] build       [8/9] compose    [9/9] e2e
```

단계 순서에는 근거가 있다 — 분 단위인 `[9/9]` 앞에 2초짜리 정적 검사를 두어,
오타 하나로 도커 스택을 띄우지 않는다.

`[5/9] 인용`을 처음부터 갖고 시작한다. 사라질 자리(계획 문서와 세션
스크래치패드)를 코드·문서 주석에서 인용하지 않는다는 규칙이고, nextjs
저장소는 이 규칙을 **사람의 기억에 두었다가 세 번 실패한 뒤** 게이트로
옮겼다. 같은 실패를 반복할 이유가 없다.

### 8.2 무엇을 무엇이 지키는가

| 대상                                                    | 지키는 것    |
| ------------------------------------------------------- | ------------ |
| `lib/*` 순수 함수 — 쿼리 조립, 그리드 상태, 일괄 실행기 | 단위         |
| 화면이 그 함수들에 **무엇을 넘기는가**                  | E2E          |
| Server Action 왕복, 제출 중 상태, 부분 실패             | E2E          |
| 세 백엔드의 계약 동일성                                 | E2E 매트릭스 |

가운데 행이 이 패밀리가 실측으로 배운 자리다. 단위는 함수를 직접 부르므로
**함수는 지켜지고 화면이 넘기는가가 안 지켜진다** — nextjs 에서
`Accept-Language`를 `null`로 바꾸는 뮤턴트가 게이트 8단계를 전부 통과한 기록이
있다. 어드민의 새 화면도 같은 함정을 갖는다.

### 8.3 3-백엔드 매트릭스

CI 전용이다. 로컬 게이트는 정본 FastAPI 하나로만 돈다 — 매번 세 스택을 띄우면
게이트가 개발 흐름을 막는다.

### 8.4 성공 기준

1. `./scripts/check.sh`가 아홉 단계 전부 초록이다.
2. 세 백엔드(`fastapi` · `nestjs` · `rails`) 각각에서 E2E 가 통과한다.
3. 알려진 계약 차이가 0건이고, **0건이라는 값이 매 실행 출력된다** — 침묵은
   "안 돌았다"와 구별되지 않는다.
4. 5.1 의 다섯 화면이 전부 있고, `/login` 밖의 넷이 익명 접근에서
   `/login?next=<원래 경로>`로 보내진다.
5. 일괄 작업이 부분 실패를 행별로 내고, 실패한 행만 재시도된다.

하위 `AGENTS.md`가 로컬 계약을 소유할 자리: `lib/jsonapi/` ·
`lib/resources/` · `lib/grid/` · `lib/bulk/` · `lib/auth/` · `app/` ·
`components/` · `scripts/` · `test/` · `docs/`.

근거는 **사실 문장으로** 적는다 — "무엇을 쟀고 결과가 무엇이었는가"를 그
자리에 쓰면 원본 문서가 사라져도 근거가 남는다.

## 10. 넣지 않는 것

| 제외                    | 이유                                                         |
| ----------------------- | ------------------------------------------------------------ |
| 역할·권한 UI            | 백엔드 계약 없음 — `role`·`permission` 모델 부재(2.3)        |
| 감사로그                | 백엔드 계약 없음 — `audit_log` 모델 부재(2.3)                |
| 사용자 관리 화면        | `GET /users/me` 하나뿐(2.1)                                  |
| `/register` 화면        | 운영자는 셀프 가입하지 않는다 — 시드로 대체(7장)             |
| 계약 실험실 `(lab)`     | `template-typescript-nextjs`가 이미 소유(5.2)                |
| 제네릭 화면 생성기      | 라우트는 손으로 만든다 — nextjs 스펙 1.1 의 판정을 따른다    |
| 일괄 작업 보상 트랜잭션 | 백엔드 계약 없음 — 취소는 "남은 요청을 내지 않는다"까지(6.4) |
| 백엔드 어댑터 계층      | 세 백엔드의 공개 계약이 통일되어 있다(1.1)                   |

앞의 셋은 **어드민에서 가장 먼저 기대되는 기능들이다.** 그래서 배제 이유를
측정과 함께 남긴다 — 나중에 이 목록을 읽는 사람이 "왜 없나"가 아니라 "백엔드에
무엇이 생기면 가능한가"를 알 수 있어야 한다.

## 11. 구현 계획이 정할 것

설계가 요구사항만 정하고 구체값을 남긴 자리다. 전부 결정 가능한 항목이고,
미정으로 남는 요구사항은 없다.

1. **~~그리드 UI 의 구현 수단~~ — 3.4 가 정했다.** `dashboard-01` 의
   `data-table.tsx`(TanStack Table)를 쓰고, 서버와의 경계는 4.2 가 고정한다.
   이 항목은 더 이상 열려 있지 않다.
2. **일괄 작업의 상한과 동시성 값**(6.2). 선언된 자리 하나에 있고 화면이 그
   값을 읽는다는 요구사항은 고정이다.
3. **출처 커밋 기록의 위치와 그것을 확인하는 검사**(3.3).
4. **대시보드가 무엇을 세는가**(5.1). 자원 카운트는 `page[size]=1`의 메타
   총합으로 얻을 수 있다 — 실제 쿼리 모양은 구현이 정한다.
