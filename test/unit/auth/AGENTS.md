# auth

인증의 순수 판단, 쿠키 직렬화와 백엔드 요청 조립을 검증한다. 실제 요청 스코프의
쿠키 읽기·쓰기와 화면 이동은 브라우저 테스트가 담당한다.

## 주요 파일

| 파일                  | 역할                                                              |
| --------------------- | ----------------------------------------------------------------- |
| `tokens.test.ts`      | 토큰 문서의 만료 시각 계산과 60초 회전 경계                       |
| `session.test.ts`     | 쿠키 와이어 형식·이름·속성·수명과 쓰기/삭제 목록의 일치           |
| `rotation.test.ts`    | 회전·통과·파기 판단과 실제 요청 조립·성공/거절/네트워크 실패 해석 |
| `credentials.test.ts` | 가입·로그인 문서·폼 입력·토큰 결과와 두 호출의 연결               |
| `flow.test.ts`        | 안전한 복귀 경로, 오류 상태, 가입 뒤 로그인 실패와 성공 계획      |
| `logout.test.ts`      | refresh 토큰 폐기 요청과 실패해도 쿠키를 지우는 호출 순서         |
| `guard.test.ts`       | 안쪽 가드의 관측 한계와 프록시가 보내는 로그인 목적지의 일치      |

## 작업 규칙

- `cookies()`·`redirect()`를 스텁하지 않는다. 요청 스코프 밖에서 던진다는 검사는
  가드의 성공 증명이 아니라 단위 테스트의 한계를 명시하는 것이다.
- 이메일·비밀번호, access·refresh 토큰, 두 만료 기간은 서로 다른 값으로 둔다.
  백엔드 주소·언어·복귀 기본값도 제품 기본값과 구별되는 프로브를 사용한다.
- 시간을 받는 함수에는 고정 `now`를 주입한다. 만료 경계는 경계값과 양쪽을 검사한다.
- 합성 오류는 코드 문자열과 실제 백엔드 오류를 구별하는 입력으로 검사한다.
  최종 쿠키 상태만 보지 않고 로그아웃의 호출 횟수와 순서도 고정한다.
- 요청 테스트의 `fetch` 스텁과 모듈 상태는 각 파일의 `afterEach`에서 정리한다.

## 검증과 의존성

루트에서 `pnpm exec vitest run test/unit/auth`를 실행한다. `lib/auth/`와
`lib/jsonapi/`, `proxy.ts`, 인증 Action에 의존하며 Vitest와 실제 `NextRequest`를
사용한다. 요청 스코프의 왕복은 `test/e2e/auth.spec.ts`, 전체 검증은 `./scripts/check.sh`다.
